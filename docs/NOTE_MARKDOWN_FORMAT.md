# レシピノートの Markdown フォーマット

AI と相談して作ったレシピを、Markdown で貼り付けてレシピノートにするための仕様（#177）。
パーサは `src/lib/recipe/note-markdown/`。

## 前提: LINE ではパース結果がそのまま登録される

取り込みの**主ルートは LINE**（#208）。トークに Markdown を送ると、パースして**確認画面なしで**
ノートとレシピを登録する。Web の貼り付け（#178）はプレビューと編集を挟む副ルート。

このためパーサは次の方針で作っている。Web 前提（後でユーザーが直す）で緩めないこと。

- **推測で混ぜない。** 読めない行は材料・手順に入れず、読み飛ばして警告にする
- **例外を投げない。** 読めた分と警告を返す。登録してよいかは結果の `registrable` で判定する
- **登録の可否はパーサだけが決める。** 呼び出し元（#208 / #178）は条件を書き直さない

## フォーマット

```markdown
[レシピ入力]
# 鶏むね肉のレモン蒸し
調理時間: 20分

## 材料（2人分）
- 鶏むね肉 300g
- レモン 1/2個
- 酒 大さじ2

## 手順
1. 鶏むね肉をそぎ切りにして塩をふる
2. 耐熱皿に並べ、レモンと酒をかける
3. ラップをして600Wで6分加熱する

## メモ
冷蔵で2日
[ここまで]
```

| 要素 | 書き方 | 取り込み先 |
|------|--------|-----------|
| 接頭語 | `[レシピ入力]` だけの行 | なし（LINE で検索ワードと区別するため） |
| 終端マーカー | `[ここまで]` だけの行 | なし（それより後ろの締めの言葉を捨てるため） |
| タイトル | 最初の見出し | `title` |
| 調理時間 | `調理時間: 20分` の行（タイトル直下かメモの中） | `cookingTimeMinutes` |
| 人数 | `## 材料（2人分）` の括弧。または `人数: 2人分` の行 | `servings` |
| 材料 | 箇条書き。名前と分量を空白で区切る | `ingredients: [{name, amount}]` |
| 手順 | 番号付きリスト | `steps` |
| メモ | 自由文 | `memo` |

## 接頭語

`RECIPE_INPUT_PREFIX`（`prefix.ts`）が正。**AI 用プロンプトに1行目へ出力させる**（#178 / #208）。
ユーザーに付けさせると付け忘れが一番多い失敗になるため。

- 括弧のゆれ（`[]` / `【】` / 全角の `［］`）と前後の空白を許容する
- **1行目に限らない。** 行頭にあればどの行でもよく、そこより前は捨てる。AI の出力をコピーすると
  「いいですね！」のような前置きが付いてくるため。文中の言及（「先頭に [レシピ入力] を〜」）には反応しない
- `parseRecipeMarkdown` は接頭語の有無どちらでも受け付ける（Web の貼り付けにも付いて来る）
- 接頭語が無いのに材料と手順の見出しがそろっている文は `looksLikeRecipeMarkdown` で判定できる。
  LINE ではこれを検索に流さず、接頭語を付けるよう案内する（#208）

## 終端マーカー

`RECIPE_INPUT_END_MARKER`（`prefix.ts`、`[ここまで]`）。**AI 用プロンプトで最終行に出力させる。**
これより後ろを捨てるので、前置き（接頭語で切る）と締めの言葉（終端マーカーで切る）の両方を構造で切れる。

- プロンプトで「Markdown 以外は出力しない」と指示しても、締めの一文は漏れやすい。LINE はワンパスなので、
  漏れるとメモに入ったまま登録され、ノートを開くまで気付けない
- 括弧のゆれは接頭語と同じく許容する。**それだけで1行を成すときに限る**（手順の文中の言及では切らない）
- 無ければ今までどおり最後まで読む（後方互換）

## 許容する崩れ方

| 崩れ方 | 扱い |
|--------|------|
| 全体がコードフェンスで囲まれている | 最初のブロックの中身だけを読む（前後の AI の言葉は捨てる） |
| `#` の前に前置きがある | 最初の見出しより前は捨てる |
| `#` のタイトルが無い | 最初の行をタイトルにして警告する |
| 見出しの別名 | 材料 / 材料リスト / 食材 / Ingredients、手順 / 作り方 / つくり方 / 調理手順 / 下ごしらえ / 下準備 / 準備 / Steps / Instructions、メモ / ポイント / コツ / 備考 / Tips |
| 手順のセクションが複数（`## 下ごしらえ` と `## 作り方`） | 文書順につなぐ。読み取りはセクションごと |
| 見出しの書き方 | `##` 以外に `###`、`**材料**`、`【材料】`、`■材料`、`材料：` も見出しとして扱う。括弧の後ろに補足が続く `【材料】（2人分）` `【材料】2人分` も可（補足は人数になる） |
| 水平線（`---` `***` `___`） | 空行として扱う。箇条書きとして読むと「--」という材料・手順になる |
| 見出しの絵文字（`## 🥬 材料`） | 外して判定する。手順など本文の絵文字は残す |
| 番号のゆれ | `1.` `1)` `１．` `①` `(1)` `Step 1:` |
| 箇条書きのゆれ | `-` `*` `+` `・` `●` |
| 太字 | 記号を外す。**太字だけの行**は小見出し扱い（材料ではグループになる） |
| 材料のグループ（`### たれ` `【A】` `**合わせ調味料**` `(A)醤油` `◎醤油`） | **分量の側**に `大さじ1（A）` として残す。名前に付けると食材マスタとの照合で「A醤油」になって外れる |
| 記号で揃えた材料（`◎醤油 大さじ2`） | 分量を含む行は材料。記号はグループとして `大さじ2（◎）` に残す（手順で「◎を合わせる」と参照されるため）。分量を含まない `◆合わせ調味料` だけがグループ見出し |
| 名前と分量の区切り | 空白（全角含む）、`：`、`…`、空白なし（`卵2個`） |
| 分量の書き方 | `大さじ1と1/2`（`と` は数字に挟まれたときだけ）、範囲の `〜` `~` と全角チルダ `～`（Windows の IME が出す） |
| 手順の折り返し | 前の手順にそのままつなぐ |
| 手順の子箇条書き | 前の手順の続きにする。前の文が句読点で終わっていなければ「。」を挟む |
| 調理時間の範囲（`20〜30分` `30分〜1時間`） | 長いほうを取る。単位がまたがっても後ろ側を単独で読む |
| 改行が CRLF | LF に揃える |

## 読み飛ばすもの

| 対象 | 扱い |
|------|------|
| **未知の見出し**（`## アレンジ: 時短`） | 中身ごと無視して警告する。**エラーにしない**。将来セクションを足したときに古いパーサが壊れないため（Epic #172 の「将来の拡張」）。未知の見出しより深い `### 材料` も本体に混ぜない |
| 手順の中で、空行の後にある番号なしの文 | 読み飛ばして警告する（AI の締めの言葉） |
| 材料の中の文章（`※` で始まる・`。` を含む・30文字超） | 読み飛ばして警告する（注意書き） |

### 既知の限界: 終端マーカーが無いと、最後のメモに締めの言葉が入る

メモは自由文なので、締めの言葉（「ぜひ作ってみてください！」）と中身では区別できない。区別しようとすると
正しいメモを捨てる側に倒れるので、パーサは推測しない。**終端マーカーで構造として切る。**
AI がマーカーを出し忘れたときだけこの限界が残る（メモは検索に使われず、後からノートの画面で直せる）。

## 表は使わない（来たら登録を止める）

材料を `| 鶏むね肉 | 300g |` のような表で書くのは**フォーマット違反**。AI 用プロンプトで禁止する。
それでも本文に表の行があれば、**登録を止めて理由を返す**（読める分だけ登録することはしない）。

- 2列の表なら読み取ること自体はできるが、あえて読まない。黙って一部だけ登録すると、表にあった材料が
  抜けていることにユーザーが気付けない。「なぜ入っていないのか」と迷わせるより、はっきり跳ね返して
  AI に出し直してもらうほうがよい
- 表の行は材料・手順・メモのどこにも入れない
- 判定は本文（接頭語・終端マーカー・フェンスで切った後）の中だけ。前置きや締めの言葉の中の表は対象外
- `|` を含むだけの行（`塩|胡椒`）は表とみなさない。`|` で始まり `|` で終わる行だけが表

## 登録してよいかの判定

`registrable` が false のとき、理由は `blockingReasons` に入る（LINE ではそのまま返信に使う）。

| 条件 | 理由 |
|------|------|
| タイトルがある | `タイトルがありません` |
| 材料が1件以上ある | `材料がありません`（食材検索に載せるのが目的なので） |
| 表を含まない | `表が含まれています。表を使わない形式で出力し直してください` |

手順が無いのは登録を止めず、警告だけにする。

## 材料の名前は正規化しない

`normalizeIngredientName()` は使っていない。あれは食材マスタとの照合用にブランド名や切り方まで
削るので、表示用の名前に使うと「キッコーマン醤油」が「醤油」になる。照合は保存時にサーバー側で
別に走る（`/api/notes`）。パーサが判定するのは「分量らしさ」だけ（`ingredient-line.ts`）。
